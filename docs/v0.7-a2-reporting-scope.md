## 1. Overview

This document specifies the shared backend reporting foundation implementing:
1. Reporting filter validation and normalization.
2. Default reporting date range resolution.
3. Authenticated user reporting scope resolution.
4. Robust scope escalation prevention across Staff, Manager, Admin, and Executive/BGH roles.

Linked specification: [`docs/v0.7-dashboard-data-inventory.md`](v0.7-dashboard-data-inventory.md).

---

## 2. Filter Types & Contracts

- **`ReportingFilterRequest`**: Raw incoming query parameters (`date_from`, `date_to`, `organization_unit_id`, `employee_id`, `source_id`, `metric_id`, `kpi_id`, `status`).
- **`NormalizedReportingFilters`**: Validated and sanitized filters with enforced date ranges and UUID formats.

---

## 3. Validation Rules

- **Date formats:** Must conform to `YYYY-MM-DD`.
- **Date range:** `date_from` must not be after `date_to`. If violated, rejects with HTTP 400.
- **Defaults:** If `date_from` or `date_to` is omitted, defaults to the first day of the current calendar month through the current date.
- **Identifiers:** All optional ID fields (`organization_unit_id`, `employee_id`, `source_id`, `metric_id`, `kpi_id`) are strictly validated against standard UUID format regex.
- **Status:** Validated against a white-list of known business statuses (`active`, `completed`, `in_progress`, `approved`, `locked`, etc.).

---

## 4. Role-Based Scope Resolution

### Staff / Viewer
- Restricted exclusively to own employee ID (`employee_ids = [viewer_user_id]`).
- Cannot request other employees or unauthorized units.

### Manager
- Resolves primary unit and all recursive descendant units via `resolveManagerScopeUnits`.
- Resolves all employee IDs belonging to the permitted unit scope.
- Enforces that requested unit/employee filters lie strictly within the permitted unit/employee scope.

### Admin
- System-wide reporting access (`is_system_wide = true`).
- Filters are fully validated against active system units and profiles.

### Executive / BGH
- Organization-wide read-only reporting access (`is_system_wide = true`, `is_read_only = true`).
- Cannot execute mutations.

---

## 5. Security & Scope Escalation Prevention

- Inactive or missing users rejected with HTTP 401/403.
- Unknown roles rejected with HTTP 403.
- Staff attempting to view other employees rejected with HTTP 403.
- Manager attempting to view out-of-scope units/employees rejected with HTTP 403.
- Request filters cannot override authenticated user identity.
