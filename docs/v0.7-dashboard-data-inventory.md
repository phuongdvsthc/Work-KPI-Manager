## 2. Dashboard Metric Definitions

### TASKS
- **Total tasks:** Count of tasks within authorized scope.
- **Completed tasks:** Count of tasks where `status = 'completed'` (or equivalent completed status).
- **In-progress tasks:** Count of tasks where `status = 'in_progress'` / active.
- **Overdue tasks:** Tasks where `due_date < current_date` and status is not completed/cancelled (backend-authoritative).
- **Due soon:** Tasks where `due_date` is within the next 3 days.
- **Completion rate:** `(completed_tasks / total_tasks) * 100` (handled safely if total_tasks = 0).

### DAILY REPORTS
- **Expected reporting days:** Business days within the requested date range.
- **Submitted reports:** Count of submitted daily report records per employee/unit.
- **Missing reports:** Expected reporting days minus submitted reports for active days.
- **Onsite days / Remote days / Off days / Business-trip days:** Breakdown by `work_mode` (`onsite`, `off`, `remote`, `business_trip`).

### METRICS
- **Total metric values:** Sum or aggregate of `metric_entries.value` filtered by date range and source/metric.
- **Breakdown by source:** Aggregation grouped by `report_source_id`.
- **Breakdown by employee:** Aggregation grouped by `user_id`.
- **Trend by date:** Time-series series grouped by `entry_date`.

### KPI
- **Assigned KPI count:** Total active KPI assignments in scope.
- **KPI progress:** Current live actual vs target achievement percentage.
- **Achieved KPI:** Count of KPIs where achievement >= 100%.
- **At-risk KPI:** KPIs where achievement is below expected trajectory.
- **Overdue KPI:** KPI assignments past due period without approval/lock.
- **Achievement rate:** Average achievement percentage across scored KPI items.

### ANNOUNCEMENTS AND NOTIFICATIONS
- **Unread notifications:** Count of notifications where `is_read = false` for the authenticated user.
- **Unacknowledged required announcements:** Published announcements requiring acknowledgment where the user has not recorded an acknowledgment.
- **Pending manager actions:** Daily report missing items, KPI reviews awaiting approval.

## 4. Reporting Filter Contract

All future dashboard and reporting APIs will accept a standardized query/filter contract:

```ts
export interface ReportingFilterContract {
  date_from?: string; // ISO date string (default: start of current month)
  date_to?: string; // ISO date string (default: end of current month)
  organization_unit_id?: string; // UUID of target organization unit
  employee_id?: string; // UUID of specific employee/user
  source_id?: string; // UUID of report source
  metric_id?: string; // UUID of metric definition
  kpi_id?: string; // UUID of KPI definition/assignment
  status?: string; // Generic status filter (e.g. 'active', 'completed', 'locked')
}
```

### Contract Rules:
- **Default date range:** First day of the current month to the current date.
- **Time-zone handling:** Dates are stored as ISO strings (`YYYY-MM-DD` or UTC timestamps); server resolves dates relative to UTC/system calendar date.
- **Empty-data behavior:** Returns zero-counts, empty series arrays, and safe defaults rather than null pointers or 500 errors.
- **Permission enforcement:** Backend enforces role and scope rules (Manager scope = primary unit + descendants; Staff = own data only; Executive = authorized reporting scope). Arbitrary unit/user IDs outside authorization scope are silently filtered out or rejected with 403.
- **Invalid-filter behavior:** Malformed UUIDs or invalid ISO date formats return 400 Bad Request with standardized error contracts.

## 5. Reporting Response Contract

All future dashboard and reporting endpoints will return responses adhering to the following schema structure:

```ts
export interface ReportingResponseContract<T = any> {
  scope: {
    actor_id: string;
    role: string;
    organization_unit_id?: string;
    resolved_unit_ids: string[];
  };
  filters: ReportingFilterContract;
  summary: Record<string, any>;
  series: Array<{
    date: string;
    value: number;
    metric_name?: string;
    category?: string;
  }>;
  breakdowns: Array<{
    label: string;
    count?: number;
    value?: number;
    percentage?: number;
    metadata?: Record<string, any>;
  }>;
  warnings: Array<{
    code: string;
    message: string;
    entity_id?: string;
  }>;
  generated_at: string; // ISO timestamp
}
```
